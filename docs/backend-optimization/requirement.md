# backend-optimization - 需求文档

## 功能概述

对 backend 工程进行系统性治理优化，不新增业务功能，聚焦三大目标：

1. **安全边界加固**：补齐管理端操作权限校验、防止越权与权限提升、治理默认凭据、加固短信验证码与 Token 生命周期、收敛匿名信息暴露面。
2. **数据正确性与并发防护**：审核状态机约束、条件更新防并发、关联数据完整性校验、初始化与迁移脚本幂等化、统一分页容量限制。
3. **工程质量提升**：统一代码风格、修正 API 文档与实际契约的偏差、收紧生产配置、日志脱敏与管理操作审计、补充单元测试与 CI 静态检查。

本次优化范围仅限 backend 工程；涉及对外契约变更（匿名审核查询字段收敛、错误码新增）已标注对 native_app / admin 的影响，前端适配不在本次范围内。

## 用户故事

- 作为**管理员**，我希望普通管理员账号只能访问其角色授权的接口，防止越权操作敏感数据。
- 作为**超级管理员**，我希望系统始终保留至少一名启用的超管账号，且任何人都无法通过角色分配给自己提权。
- 作为**App 用户**，我希望重置密码后旧会话立即失效，防止令牌泄露造成持续风险。
- 作为**App 用户**，我希望多个设备同时登录时，退出登录只影响当前设备。
- 作为**App 用户**，我的手机号和审核备注不希望被任何知道手机号的陌生人查询到。
- 作为**运维人员**，我希望生产环境缺少必需配置（数据库口令、初始管理员口令）时启动直接失败，而不是带弱默认值上线。
- 作为**运维人员**，我希望升级脚本是幂等的，重复执行或中途失败后重跑不会破坏已有菜单和授权数据。
- 作为**审计人员**，我希望管理端的敏感操作（审核、授权、账号增删）有不可抵赖的操作日志。
- 作为**开发者**，我希望 CI 能拦截风格问题和依赖漏洞，单元测试覆盖新增的安全与并发分支。

## 非功能性需求

- **安全**: 密码继续使用 Argon2；验证码生成使用 `SecureRandom`；Redis 原子操作优先使用 Lua 脚本；任何日志不输出明文密码/验证码。
- **兼容性**: 保持既有技术选型（Spring Boot 4 + MyBatis-Plus + Sa-Token），不引入 Spring Security、Flyway/Liquibase；响应继续使用 `Result<T>` 包装，业务异常保持 HTTP 200 约定。
- **性能**: 权限校验复用 Sa-Token 缓存；审计日志写入同步但隔离异常（记录失败不影响主流程）；不新增高频接口。
- **可测试性**: 全部新增业务分支按 `backend/.qoder/rules/testing-convention.md` 用 JUnit5 + Mockito 覆盖，不引入 `@SpringBootTest`。

## 边界条件与异常场景

| 场景 | 触发条件 | 预期行为 |
|------|----------|----------|
| 无权限访问管理接口 | 已登录但角色未授权对应权限码 | HTTP 403 + code 403 |
| 并发重复审核同一用户 | 两个管理员同时提交审核 | 先提交者成功，后提交者收到 10019（已审核） |
| 并发刷新同一 Refresh Token | 同一 Token 两个并发请求 | 仅一个成功，另一个收到 10016 |
| 重置密码后旧 Token 使用 | 旧 access/refresh token | 全部失效，收到 401/10016 |
| 多设备退出 | 设备 A、B 同时登录，A 退出 | 仅 A 的 token 与 refresh 失效 |
| 验证码连续输错 | 同一手机号同场景错误 5 次 | 验证码作废，需重新获取（10022） |
| 唯一键冲突（复用已删除手机号/用户名/角色编码） | 插入命中历史唯一键 | 409 + "资源冲突"，不再返回 500 |
| 菜单父节点成环 | parentId 指向自身或后代 | 拒绝保存（20104） |
| 禁用/删除最后超管 | 系统仅剩一名启用超管 | 拒绝操作（20305） |
| prod 缺少必需环境变量 | DB_PASSWORD / ADMIN_INITIAL_PASSWORD 为空 | 启动失败并明确报错 |
| prod 调用发送验证码 | 未配置真实短信供应商 | 返回"短信服务未配置"业务错误，不静默丢弃 |
| 删除后账号标识复用 | 业务查重通过但唯一键占用 | 见上"唯一键冲突"行，统一 409 |

## 关键业务决策（默认已选，审核时可改）

| # | 决策点 | 默认方案 | 备选方案 |
|---|--------|----------|----------|
| D1 | 匿名审核查询隐私 | **方案A**：仅返回 `auditStatus` + 脱敏手机号，移除 `auditRemark`/`nickname`/`createTime`；驳回原因仅在登录失败错误信息中返回。App 审核页"驳回原因"行将不再展示（条件渲染，不崩溃），后续可另行规划 App 适配 | 方案B：保留字段，仅加限流（缓解枚举但不解决隐私暴露） |
| D2 | 逻辑删除与唯一键 | 已删除记录的手机号/用户名/角色编码**永久占用**唯一键，不允许复用；冲突统一返回 409 | 允许复用（需改唯一键结构，涉及数据迁移，不建议） |
| D3 | 初始管理员口令 | dev 保持 `admin123` 便于本地调试；prod 从环境变量 `ADMIN_INITIAL_PASSWORD` 注入，缺失则启动失败；日志仅输出用户名 | prod 随机生成口令打印一次（仍有泄露窗口） |
| D4 | 管理端权限粒度 | 路由级映射，权限码与现有菜单数据一致；App 用户的创建/更新/删除暂归入 `user:list`（现有菜单无对应按钮权限码，避免本次扩散改菜单种子数据） | 本次同步补充 user:create/update/delete 按钮权限码（需改菜单数据与前端） |
