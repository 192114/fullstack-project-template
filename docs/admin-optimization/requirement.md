# Admin 工程优化 - 需求文档

## 功能概述

基于 2026-09-22 对 admin 工程的全量审查结论（24 项），对 **admin（React 19 + Vite 管理后台）** 进行系统性修复与优化，并由 **backend（Spring Boot）** 提供少量配合改动（服务端筛选、菜单父级校验）。

目标：

1. 修正影响功能正确性的缺陷（筛选语义、错误态、竞态、防重复提交、分页边界、表单校验、退出注销、缓存失效、会话隔离）
2. 补齐工程化门禁（类型检查、格式化、CI 覆盖、环境校验、依赖治理）
3. 改善首屏与运行时性能（路由分包、搜索防抖、请求取消、图片压缩）
4. 提升可维护性与可访问性（公共业务组件、Toast 反馈、语义 Token/暗色、键盘可达、测试）

明确不做：更换技术栈、引入大型 CRUD 框架、全量迁移 `features/` 目录结构、后端鉴权体系重构。

## 用户故事

- 作为管理员，我希望角色/状态筛选作用于全部数据而非当前页，以免误判数据规模与结果。
- 作为管理员，我希望请求失败时看到明确的错误提示和重试入口，而不是"暂无数据"。
- 作为管理员，我希望连续打开不同角色的权限分配时，加载结果不会串单。
- 作为管理员，我希望审核、启停等操作有防重复提交保护，提交中不会误关弹窗影响其他对象。
- 作为管理员，我希望删除末页最后一条数据后自动回到有效页码，不会停在空页。
- 作为管理员，我希望退出登录时服务端会话一并注销，而不仅是清理本地 Token。
- 作为管理员，我希望角色/菜单权限变更后，按钮、侧栏菜单与路由守卫及时刷新。
- 作为管理员，我希望在另一标签页登录/退出后，本页会话状态能正确同步。
- 作为开发者，我希望 CI 能拦住类型错误、格式问题与核心逻辑回归，类型检查脚本不是空跑。
- 作为开发者，我希望生产/预发构建时能拦截占位环境变量（example.com）。
- 作为运维，我希望 admin 有可复用的生产部署配置（Nginx SPA 回退、静态缓存、gzip）。
- 作为使用屏幕阅读器/键盘的用户，我希望分页、菜单树、图标按钮有可访问名称与状态语义。

## 非功能性需求

- 性能：首包 JS（gzip）目标从 314KB 降至 ≤ 200KB；登录背景图 ≤ 200KB；列表翻页保留上一页数据避免闪烁
- 兼容性：Chrome/Edge/Safari/Firefox 最近两个大版本；不降级到 ES2023 以下
- 安全：不新增敏感信息存储；错误提示不泄露内部堆栈；401 处理不误伤新会话
- 可访问性：图标按钮具备可访问名称；分页具备导航语义（aria-current）；表单错误与控件关联
- 可维护性：mutation/查询失效/toast 统一模式，后续页面可复制

## 边界条件与异常场景

| 场景 | 触发条件 | 预期行为 |
|------|----------|----------|
| 末页删除唯一记录 | 第 N 页仅 1 条，删除后 totalPages 变为 N-1 | 自动回退到 N-1 页；总页数 ≤ 1 时仍显示"共 N 条" |
| 角色筛选无匹配用户 | `roleId` 下无任何关联用户 | 服务端返回空页，前端显示空态而非错误 |
| 快速连续点击角色 A/B | 打开 A 后立即打开 B | 弹窗数据始终与标题角色一致，保存前校验归属 |
| 提交中关闭弹窗 | 请求进行中点击遮罩/取消 | 拦截关闭或忽略过期回调，不影响后续新对象操作 |
| 旧请求晚到 401 | 重新登录后旧请求才失败 | 不清除新 token、不跳登录 |
| 跨标签退出 | 标签 1 退出登录 | 标签 2 收到 storage 事件，清缓存并跳登录 |
| 菜单父级成环 | 编辑菜单将父级设为自身/后代 | 后端拒绝（20104），前端选项中即排除 |
| 权限自变更 | 管理员调整自己角色的菜单 | 权限、侧栏、路由守卫立即重算 |
| 生产构建占位环境 | VITE_API_BASE_URL 含 example.com | 构建前置校验直接失败 |
| 取消的查询报错 | 防抖切换导致旧请求被取消 | 不 toast、不重试，静默忽略 |
